# PDF Intelligence System (ChatPDF)

**Chat with your PDFs, locally.** PDF Intelligence is a Streamlit question-answering app built with
**Retrieval-Augmented Generation (RAG)**. Upload one or more PDFs, process them, and ask questions in
natural language. Answers are grounded in retrieved passages and include page-level source citations.

---

## Project Overview

This application lets users upload **one or more PDF documents** and ask **natural-language
questions** about them. Instead of searching a PDF by hand, you ask a question in plain language
and the app retrieves the most relevant passages from your documents and answers using them.

At runtime, embeddings are computed locally with the Hugging Face
`sentence-transformers/all-MiniLM-L6-v2` model, vectors are stored in an in-memory **FAISS** index,
and answers are generated by **Ollama** using `llama3.2`. No API key or hosted LLM account is
required. An internet connection is needed initially to install Python packages and download the
embedding model and Ollama model.

## Highlights

- Process multiple PDFs in one session, with page-level indexing and per-file status.
- Ask questions and follow-ups in natural language; narrow retrieval to one uploaded document when
  needed.
- See citations to the actual source PDF and page used for each answer.
- Inspect retrieved chunks in the developer debug panel.
- Keep document processing, embeddings, and answer generation on your own machine.

## Features

Implemented in the current version:

- **Multiple PDF upload** — `st.file_uploader(accept_multiple_files=True, type=["pdf"])`.
- **Page-aware PDF text extraction** — page-by-page extraction with `PyPDF2.PdfReader`; every
  successfully extracted page becomes its own `Document`, so pages are never merged.
- **Metadata on every chunk** — each chunk carries `source` (file name), `page` (1-based page
  number), `document_id` and `chunk_id`; the metadata survives chunking, embeddings, FAISS and
  retrieval.
- **Text chunking** — `RecursiveCharacterTextSplitter`, 1000 characters per chunk with 200 characters
  overlap (unchanged).
- **Local embeddings** — `sentence-transformers/all-MiniLM-L6-v2`, run on CPU via `langchain-huggingface`.
- **FAISS vector store** — in-memory similarity index (`langchain-community` + `faiss-cpu`).
- **Relevant chunk retrieval** — the retriever returns the best-matching chunks (default `k=4`).
- **Source citations** — each answer is followed by the documents and pages the retriever actually
  used, de-duplicated and escaped (for example `📄 DBMS.pdf — Page 4`). Nothing is invented: if the
  retriever returns nothing, no sources are shown.
- **Grounded answers** — every retrieved chunk is labelled `[Source: <file>, Page: <number>]` in the
  prompt, and the model is instructed to answer only from that context. When the context does not
  contain the answer it replies: *"I could not find that information in the uploaded documents."*
- **Document filtering** — a sidebar **Search in** selector limits retrieval to a single document
  while keeping the conversation.
- **Conversational memory** — `ConversationBufferMemory` keeps the transcript, and a condense-question
  prompt rewrites follow-up questions into standalone questions, so *"who walked on the surface during
  that mission?"* is resolved against the earlier turn.
- **Local LLM answers** — `ChatOllama(model="llama3.2", temperature=0.2)` generates the answer from the
  retrieved context.
- **Streamlit UI** — sidebar upload + `Process` button, indexed-document list with per-file page/chunk
  counts, question form, chat transcript with user/assistant bubbles, avatars and a sources block.
- **Partial-failure reporting** — empty pages and pages that fail to extract are reported per file, and
  the remaining pages are still indexed.
- **Retrieval debug panel** — a collapsed `🔍 Retrieval debug` section lists the retrieved chunks with
  file, page, chunk id and distance (chunk text previews only on request).
- **Error handling & escaping** — unreadable/corrupt PDFs, PDFs without extractable text (scanned),
  asking before processing, and ingestion/LLM failures are reported in the UI instead of crashing, and
  all message/citation text is HTML-escaped.

## RAG Workflow

```
PDF upload (one or many)
        |
        v
Page-aware extraction      PyPDF2.PdfReader -> page.extract_text() per page
        |                  (empty / failed pages are reported and skipped)
        v
Chunking                   RecursiveCharacterTextSplitter (chunk_size=1000, overlap=200)
        |                  one Document per chunk, metadata kept:
        |                  source, page, document_id, chunk_id
        v
Embeddings                 sentence-transformers/all-MiniLM-L6-v2 (CPU)
        |
        v
Vector store               FAISS.from_documents(...)  (in memory, per session)
        |
        v
Retrieval                  similarity search, optionally filtered to one document
        |                  -> top matching chunks, each with its source and page
        v
Context for the model      "[Source: file.pdf, Page: n]" + chunk text
        |                  (+ conversation memory / condense-question prompt)
        v
Answer generation          Ollama -> llama3.2 (temperature 0.2), grounded in that context
        |
        v
Answer + sources           "Sources: 📄 file.pdf — Page n" in the Streamlit UI
```

## Requirements

- **Python 3.10 or newer** — developed and verified with **Python 3.13.9** on Windows.
- **Ollama** installed and running, with the **`llama3.2`** model pulled (see *Ollama Setup*).
- **Python packages** (installed from `requirements.txt`): `streamlit`, `PyPDF2`, `python-dotenv`,
  `langchain-core`, `langchain-classic`, `langchain-community`, `langchain-text-splitters`,
  `langchain-huggingface`, `langchain-ollama`, `faiss-cpu`, `sentence-transformers`, `torch`.
- An internet connection for the initial package/model downloads, plus enough disk space and memory
  for the models. The embedding model is roughly 90 MB; `llama3.2` is a ~2 GB download.


## Ollama Setup

The application **requires Ollama** — there is no cloud/API fallback. If Ollama is not running,
every question fails with a connection error.

1. Install Ollama from <https://ollama.com/download> and make sure it is running. The desktop app
   starts the server automatically; the API listens on `http://localhost:11434`.
2. Pull the model the application uses:

   ```bash
   ollama pull llama3.2
   ```

3. Verify the model is available:

   ```bash
   ollama list
   ```

   You should see `llama3.2` in the list.

The model name is currently hard-coded in `app.py`:

```python
llm = ChatOllama(model="llama3.2", temperature=0.2)
```

## Environment Variables

**No environment variable is required, and none is read by the code.**

`app.py` calls `load_dotenv()` at startup, so an optional `.env` file is loaded if you create one,
but the application does not read any configuration value from it — there is therefore no
`.env.example` file. No API key is needed because the LLM runs locally through Ollama.

## Running the Application

From the `pdf_chat` directory, with Ollama running:

```bash
streamlit run app.py
```

Streamlit uses its default port and prints the local URL:

```
http://localhost:8501
```

The first **Process** click may download the embedding model (~90 MB), and the first question makes
Ollama load `llama3.2` into memory, so the first interactions are usually the slowest.

## Usage

1. **Start Ollama** (desktop app, or `ollama serve`) and make sure `llama3.2` has been pulled.
2. **Start Streamlit** with `streamlit run app.py` and open <http://localhost:8501>.
3. **Upload one or more PDFs** with the sidebar file uploader.
4. **Click `Process`** — the app extracts the text page by page, splits it into chunks, embeds them and
   builds the FAISS index. The sidebar then lists every indexed document with its page and chunk
   counts (`Indexed documents (2) — ✓ A.pdf — 2 page(s), 2 chunk(s)`), and reports any page that was
   empty or could not be extracted. Processing new files replaces the previous document set and
   clears the transcript.
5. **Ask questions** in the text box and submit with **`Ask`**.
6. **Read the answer and its sources** — every answer is followed by the documents and pages the
   retriever used, for example `📄 A.pdf — Page 2`. If the retrieved context does not contain the
   answer, the app says it could not find the information instead of guessing.
7. **Optionally narrow the search** with the sidebar **Search in** selector (`All documents` or one
   specific file). Only chunks of the selected document are retrieved; the conversation is kept.
8. **Ask follow-up questions** — earlier turns are kept in memory, and follow-ups such as
   *"and who walked on the surface during that mission?"* are rewritten into standalone questions
   before retrieval.
9. **Developers:** open the collapsed **🔍 Retrieval debug** section below the transcript to see which
   chunks were retrieved for the last answer (document, page, chunk id, distance), with chunk text
   previews shown only on request.

## Tests

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests -v
```

The suite covers page-aware ingestion and metadata, empty/unreadable pages, duplicate file names,
metadata survival through FAISS and retrieval, grounding and citation behaviour, follow-up questions,
document filtering, the Streamlit UI flow, and escaping/CSS regressions. Deterministic tests use a
fake chat model. Tests that require a live Ollama server and `llama3.2` are skipped automatically
when either is unavailable. The suite still needs the runtime Python dependencies and may download
the embedding model for FAISS tests.

## Local processing and privacy

The app uses a local Ollama server for answer generation and computes embeddings locally. It does
not require an API key or send prompts to a hosted LLM provider. The first setup does download
packages and model files from their respective providers. PDFs and chat history are held in the
active Streamlit session; the app does not persist them to a database.

## Limitations

These are the known limits of the currently implemented architecture:

- **Session-only index and history** — the FAISS index and conversation live in Streamlit session
  state. They are not saved or shared, and reprocessing replaces the current document set.
- **No OCR** — scanned/image-only pages have no extractable text and are skipped and reported.
- **Fixed RAG configuration** — chunk size/overlap, embedding model, retrieval count (`k=4`), and
  LLM are configured in the code; there is no UI for changing them, reranking, or score thresholds.
- **Ollama and one model required** — `llama3.2` is currently configured in the app; there is no
  hosted-provider fallback or model picker.
- **Conversation memory grows with the session** — the transcript is retained for follow-up questions
  without a configured window or summarization.
- **No streaming** — the answer appears after generation completes.
- **No explicit upload or question-size limits** are configured.
- **Single-user app** — there is no authentication or multi-user data isolation; run it in a trusted
  environment.
- **PDF extraction quality varies** — text extraction may be imperfect for complex layouts, tables,
  or multi-column pages.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `Error while answering: [WinError 10061] No connection could be made ...` (or `Connection refused`) | Ollama is not running | Start the Ollama app, or run `ollama serve`, then ask the question again |
| Error mentioning `model "llama3.2" not found` | The model was never pulled | `ollama pull llama3.2` (check with `ollama list`) |
| `ModuleNotFoundError: No module named 'streamlit'` / `'langchain_*'` / `'faiss'` / `'sentence_transformers'` | Dependencies are not installed in the interpreter that runs Streamlit | `python -m pip install -r requirements.txt` using the same Python/venv you launch Streamlit with |
| `Could not read <file>: ...` or **"No readable text found in the uploaded PDF(s)"** | Scanned / image-only PDF, password-protected or corrupt file | Run OCR on the PDF first (this app has no OCR) or use a text-based PDF |
| The first answer takes a long time | Embedding model download (~90 MB) plus Ollama loading the model | Wait for the first request to complete; subsequent questions are faster |
| `Port 8501 is already in use` | Another Streamlit instance is running | Stop it, or start on another port: `streamlit run app.py --server.port 8502` |
| Hugging Face download warning / slow model download | No `HF_TOKEN` configured | Harmless; optionally set `HF_TOKEN` in your shell to raise the rate limit |
