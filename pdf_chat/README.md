# PDF Intelligence System (ChatPDF)

A user-centric PDF question-answering app built with **Retrieval Augmented Generation (RAG)**.
Upload one or more PDFs, click **Process**, and ask questions about their content in natural language.

---

## Project Overview

This application lets users upload **one or more PDF documents** and ask **natural-language
questions** about them. Instead of searching a PDF by hand, you ask a question in plain language
and the app retrieves the most relevant passages from your documents and answers using them.

Everything runs locally: embeddings are computed on your machine with the Hugging Face
`sentence-transformers/all-MiniLM-L6-v2` model, the vectors live in an in-memory **FAISS** index,
and answers are generated by a local LLM (**Ollama / `llama3.2`**). No API key, no OpenAI account
and no internet connection to a model provider are required.

## Features

Implemented in the current version:

- **Multiple PDF upload** — `st.file_uploader(accept_multiple_files=True, type=["pdf"])`.
- **PDF text extraction** — page-by-page extraction with `PyPDF2.PdfReader`.
- **Text chunking** — `RecursiveCharacterTextSplitter`, 1000 characters per chunk with 200 characters overlap.
- **Local embeddings** — `sentence-transformers/all-MiniLM-L6-v2`, run on CPU via `langchain-huggingface`.
- **FAISS vector store** — in-memory similarity index (`langchain-community` + `faiss-cpu`).
- **Relevant chunk retrieval** — the retriever returns the best-matching chunks (default `k=4`).
- **Conversational memory** — `ConversationBufferMemory` keeps the transcript, and a condense-question
  prompt rewrites follow-up questions into standalone questions, so *"who walked on the surface during
  that mission?"* is resolved against the earlier turn.
- **Local LLM answers** — `ChatOllama(model="llama3.2", temperature=0.2)` generates the answer from the
  retrieved context.
- **Streamlit UI** — sidebar upload + `Process` button, question form, chat transcript with
  user/assistant bubbles and avatars, progress spinner and status messages.
- **Error handling** — unreadable/corrupt PDFs, PDFs without extractable text (scanned), asking before
  processing, and ingestion/LLM failures are reported in the UI instead of crashing the app.
- **Escaped chat output** — message text is HTML-escaped before it is rendered in the chat bubbles.

## RAG Workflow

```
PDF upload (one or many)
        |
        v
Text extraction            PyPDF2.PdfReader -> page.extract_text() for every page
        |
        v
Chunking                   RecursiveCharacterTextSplitter (chunk_size=1000, overlap=200)
        |
        v
Embeddings                 sentence-transformers/all-MiniLM-L6-v2 (CPU)
        |
        v
Vector store               FAISS.from_texts(...)  (in memory, per session)
        |
        v
Retrieval                  vectorstore.as_retriever() -> most similar chunks
        |
        v
Conversational context     ConversationBufferMemory + condense-question prompt
        |
        v
Answer generation          Ollama -> llama3.2 (temperature 0.2)
        |
        v
Answer shown in the Streamlit UI
```

## Requirements

- **Python 3.10 or newer** — developed and verified with **Python 3.13.9** on Windows.
- **Ollama** installed and running locally, with the **`llama3.2`** model pulled (see *Ollama Setup*).
- **Python packages** (installed from `requirements.txt`): `streamlit`, `PyPDF2`, `python-dotenv`,
  `langchain-core`, `langchain-classic`, `langchain-community`, `langchain-text-splitters`,
  `langchain-huggingface`, `langchain-ollama`, `faiss-cpu`, `sentence-transformers`, `torch`.
- Enough disk/RAM for the model files: the embedding model is roughly 90 MB, and `llama3.2` is a
  ~2 GB download on first pull.

## Installation

```bash
# 1. Clone the repository
git clone https://github.com/kartiksrathod/Pdf_Analyzer.git
cd Pdf_Analyzer/pdf_chat

# 2. Create and activate a virtual environment (recommended)
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

# 3. Install the dependencies
python -m pip install -r requirements.txt
```

## Ollama Setup

The application **requires Ollama** — there is no cloud/API fallback. If Ollama is not running,
every question fails with a connection error.

1. Install Ollama from <https://ollama.com/download> and make sure it is running. The desktop app
   starts the server automatically; the API listens on `http://localhost:11434`.
2. Pull the model the application uses:

   ```bash
   ollama pull llama3.2
   ```

3. Verify the model is available:

   ```bash
   ollama list
   ```

   You should see `llama3.2` in the list.

The model name is currently hard-coded in `app.py`:

```python
llm = ChatOllama(model="llama3.2", temperature=0.2)
```

## Environment Variables

**No environment variable is required, and none is read by the code.**

`app.py` calls `load_dotenv()` at startup, so an optional `.env` file is loaded if you create one,
but the application does not read any configuration value from it — there is therefore no
`.env.example` file. No API key is needed because the LLM runs locally through Ollama.

## Running the Application

From the `pdf_chat` directory, with Ollama running:

```bash
streamlit run app.py
```

Streamlit uses its default port and prints the local URL:

```
http://localhost:8501
```

The first **Process** click downloads the embedding model (~90 MB) and the first question makes
Ollama load `llama3.2` into memory, so the first interactions are the slowest.

## Usage

1. **Start Ollama** (desktop app, or `ollama serve`) and make sure `llama3.2` has been pulled.
2. **Start Streamlit** with `streamlit run app.py` and open <http://localhost:8501>.
3. **Upload one or more PDFs** with the sidebar file uploader.
4. **Click `Process`** — the app extracts the text, splits it into chunks, embeds them and builds the
   FAISS index, then reports how many chunks were indexed (`Currently indexed: ...`).
   Processing new files replaces the previous document set and clears the transcript.
5. **Ask questions** in the text box and submit with **`Ask`**.
6. **Ask follow-up questions** — earlier turns are kept in memory, and follow-ups such as
   *"and who walked on the surface during that mission?"* are rewritten into standalone questions
   before retrieval.

## Limitations

These are the known limits of the currently implemented architecture:

- **In-memory FAISS only** — the vector store is rebuilt for every session; there is no persistence,
  no save/load, and no sharing between users.
- **No source citations** — chunks are indexed without file names or page numbers, so answers cannot
  point at a specific page, and retrieval cannot be filtered per document. The text of all uploaded
  PDFs is concatenated before chunking.
- **No OCR** — scanned / image-only PDFs contain no extractable text and are reported as unreadable.
- **Fixed retrieval settings** — the default retriever (`k=4`, similarity search) is used; there is no
  MMR, score threshold, reranking, or UI control over how many chunks are retrieved.
- **One local LLM** — `llama3.2` via Ollama is hard-coded; there is no OpenAI/other provider option
  and no model picker.
- **Unbounded conversation memory** — the whole transcript is kept and passed to the condense step;
  there is no windowing or summarisation.
- **No streaming** — the answer appears only after generation finishes.
- **No size limits** — no file-size, page-count, or question-length limits are enforced.
- **Single user** — no authentication or per-user isolation; all state lives in the Streamlit session.
- **Extraction quality depends on the PDF** — `PyPDF2` (upstream now recommends `pypdf`) can extract
  complex layouts, tables or multi-column pages imperfectly.
- **No automated tests or CI** in the repository.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `Error while answering: [WinError 10061] No connection could be made ...` (or `Connection refused`) | Ollama is not running | Start the Ollama app, or run `ollama serve`, then ask the question again |
| Error mentioning `model "llama3.2" not found` | The model was never pulled | `ollama pull llama3.2` (check with `ollama list`) |
| `ModuleNotFoundError: No module named 'streamlit'` / `'langchain_*'` / `'faiss'` / `'sentence_transformers'` | Dependencies are not installed in the interpreter that runs Streamlit | `python -m pip install -r requirements.txt` using the same Python/venv you launch Streamlit with |
| `Could not read <file>: ...` or **"No readable text found in the uploaded PDF(s)"** | Scanned / image-only PDF, password-protected or corrupt file | Run OCR on the PDF first (this app has no OCR) or use a text-based PDF |
| The first answer takes a long time | Embedding model download (~90 MB) plus Ollama loading the model | Wait for the first request to complete; subsequent questions are faster |
| `Port 8501 is already in use` | Another Streamlit instance is running | Stop it, or start on another port: `streamlit run app.py --server.port 8502` |
| Hugging Face download warning / slow model download | No `HF_TOKEN` configured | Harmless; optionally set `HF_TOKEN` in your shell to raise the rate limit |
